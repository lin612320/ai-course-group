# 项目一 · N-Puzzle 问题求解

用 `SearchFramework 2.1` 框架求解 8 数码和 15 数码（数字华容道），四个阶段全部达标。

## 题目要求与结果

| 阶段 | 要求 | 我们的结果 |
|---|---|---|
| 一 | 3 阶 1 秒内解出 | 最慢 0.156 s，余量 6 倍以上 |
| 二 | 4 阶与参考程序同级别 | 解长、扩展结点数与参考程序逐位一致；IDA\* 总耗时 136.2 s，参考 404.1 s |
| 三 | 倒序盘面 1 分钟内解出 | 2.62 s 达标（加权 IDA\* + 模式数据库，72 步）；另有 70 步最优解，369 s |
| 四 | 解路径可视化 | Swing 窗口动画，支持批量连播 |

## 关键技术

**数据结构**：整个盘面压进一个 64 位整数（每格 4 bit），`equals`/`hashCode` 从 O(16) 降到 O(1)，状态从 128 字节降到 48 字节。Open 表用惰性删除替代 `PriorityQueue.remove()`，并加了定期压实。

**启发函数**：
- 错位将牌数 `h = 不在位的牌数`
- 曼哈顿距离 `h = Σ(|Δr| + |Δc|)`
- 线性冲突 `h = 曼哈顿 + 2×冲突对`

**模式数据库**：15 块牌切成 5-5-5 三组，每组 5,765,760 个抽象状态，11 MB 一张表。用**代价划分**（只给自己组的牌记步数，空格蹭别人的牌不算钱）保证三张表相加仍可采纳。建表用分层 0-1 BFS：先铺满同一层的零代价闭包，再产生下一层，顺序不能反。

**加权 IDA\***：`f = g + w·h`，`w = 1.2` 时 2.62 s 解出 72 步。

## 已知限制

- 模式数据库的可采纳性我们证明了，**单调性没证出来**，理论上存在次优风险，实验中没有遇到。
- 阶段三的 1 分钟达标依赖加权，牺牲了最优性。要最优就得接受 369 秒。
- 6-6-3 划分试过，反而更慢（状态数 10 倍、建表 16 倍、启发值 45 低于 5-5-5 的 47）。
