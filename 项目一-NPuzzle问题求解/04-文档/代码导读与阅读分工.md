## 一、先用 5 分钟看懂「框架怎么转」

**一句话**：框架负责"搜索循环"，我们只负责"填空"——这叫**控制反转（好莱坞原则：别调用我们，我们会调用你）**。

```
① 运行配置
   main : core.runner.SearchTester
   args : resources/problems_stage2.txt NPUZZLE 2 stud.g01.runner.PuzzleFeeder
                                          ↑        ↑          ↑
                                       问题类型   阶段号   ★我们的 Feeder（反射创建）
                    │
                    ▼
②  SearchTester ──反射──► PuzzleFeeder          ★g01/runner
                    │       ├─ getProblems()   → 解析文件，造 NPuzzleProblem ★
                    │       ├─ getFrontier()   → 造 PqFrontier            ★
                    │       └─ getPredictor()  → 交出启发函数（曼哈顿/PDB）★
                    ▼
③  EngineFeeder.getAStar(h)  = BestFirstSearcher(frontier, predictor)   框架
                    │
                    ▼
④  BestFirstSearcher.search(problem)                                    框架
        while (true) {
          node = frontier.poll()          ◄── PqFrontier ★
          if (problem.goal(state)) 返回解  ◄── PuzzleBoard.equals ★
          for (child : problem.childNodes(node, predictor))  ◄── 框架模板方法
                ├─ state.actions()        ◄── PuzzleBoard ★
                ├─ problem.applicable()   ◄── NPuzzleProblem ★
                ├─ state.next(action)     ◄── PuzzleBoard ★
                ├─ problem.stepCost()     ◄── NPuzzleProblem ★
                └─ predictor.heuristics() ◄── 曼哈顿 / 线性冲突 / 模式数据库 ★
              frontier.offer(child)
        }
                    │
                    ▼
⑤  problem.showSolution(path)   → 控制台文字版 或 弹窗动画          ★
```

> **★ 标记的都是我们写的**。框架那几层（②③④的骨架）一行都不用改。

             └──────────────────────┴──► ExperimentRunner / PuzzleVisualizer（两种入口）

## 五、关键概念速查

| 术语 | 含义 | 出现在 |
|---|---|---|
| **g(n) / h(n) / f(n)** | 已走代价 / 到目标估计 / 二者之和 | `Node` |
| **可采纳性（admissible）** | h 永远 ≤ 真实剩余步数 ⇒ 保证最优解 | 全篇 |
| **代价划分** | 只有移动本模式内将牌才计步 ⇒ 保证可采纳 | `PatternDatabase` |
| **惰性删除** | 替换结点时不真删旧的，`poll` 时再过滤 | `PqFrontier` |
| **压实（compaction）** | 定期重建堆，扔掉废结点防止内存膨胀 | `PqFrontier` |
| **加权 IDA\*** | `f = g + w·h`，w>1 更快但可能非最优 | `IdAStar` |
| **位打包** | 16 格 × 4 bit = 64 bit，塞进一个 long | `PuzzleBoard` |
| **逆序数** | 判断盘面有无解的奇偶性依据 | `NPuzzleProblem.solvable()` |
| **控制反转** | 框架调我们，不是我们调框架 | 全篇 |

## 六、运行命令速查（工作目录都是 `WattAi`）

```bash
# 阶段一：3 阶，两个启发函数对比
java -cp out/production/WattAi stud.g01.runner.ExperimentRunner ^
     resources/problems_stage1.txt stud.g01.runner.PuzzleFeeder MISPLACED MANHATTAN

# 阶段二：4 阶，7 个实例（不要用 MISPLACED，会 OOM）
java -Xmx6g -cp out/production/WattAi stud.g01.runner.ExperimentRunner ^
     resources/problems_stage2.txt stud.g01.runner.PuzzleFeeder DISJOINT_PATTERN

# 阶段三：倒序实例（IDA* + 模式数据库）
java -Xmx4g -Dnpuzzle.weight=1.2 -cp out/production/WattAi stud.g01.runner.ExperimentRunner ^
     resources/problems_stage3.txt stud.g01.runner.PuzzleFeeder DISJOINT_PATTERN --ida

# 任务二：A* / IDA* 对标老师参考
java -Xmx8g -cp out/production/WattAi stud.g01.runner.ExperimentRunner ^
     resources/problems_idastar.txt stud.g01.runner.PuzzleFeeder MANHATTAN --ida

# 可视化演示（关掉窗口自动播下一个）
java -Xmx4g -Dnpuzzle.weight=1.2 -cp out/production/WattAi stud.g01.gui.PuzzleVisualizer ^
     resources/problems_stage3.txt NPUZZLE 3 stud.g01.runner.PuzzleFeeder DISJOINT_PATTERN --ida
```

**可选开关**：`--size=3/4`（只跑某阶）、`--ida`（改 IDA\*）、`-Dnpuzzle.weight=1.2`（加权）、`-Dnpuzzle.pdb=663|multi`（换模式划分，供对比实验）
